# Документация проекта: To-Do List (Qt / QML + C++)

## Описание проекта
Данный проект представляет собой классическое приложение "Список задач" (To-Do List), разработанное с использованием фреймворка Qt. Проект демонстрирует интеграцию графического интерфейса на базе **QML** и бизнес-логики на **C++**.

## Архитектура: Model-View-Delegate
Проект построен на паттерне Model-View-Delegate, который строго разделяет логику хранения данных и их визуальное отображение.

*   **Model (Модель - C++)**: Класс `ToDoModel`, наследуемый от `QAbstractListModel`. Отвечает за хранение списка задач, обработку запросов от интерфейса и уведомление об изменениях.
*   **View (Представление - QML)**: Компонент `ListView` в `Main.qml`. Отвечает за общую механику списка на экране (скроллинг, компоновка).
*   **Delegate (Делегат - QML)**: Компонент `TodoDelegate.qml`. Шаблон, определяющий, как визуально выглядит ровно *одна* строка в списке (текст, чекбокс, кнопка удаления).

## Подробная реализация C++ (Модель данных)

### 1. Структура данных (`ToDoItem`)
Все данные одной задачи хранятся в легковесной структуре:
```cpp
struct ToDoItem {
  QString description; // Текст задачи
  bool isDone;         // Статус (выполнена/нет)
};
```
Сами задачи хранятся во внутреннем массиве `QList<ToDoItem> m_items`.

### 2. Пользовательские роли (Roles)
Для связи QML и C++ используется система ролей. В `todomodel.h` определен `enum`:
```cpp
enum ToDoRoles { 
    DescriptionRole = Qt::UserRole + 1, 
    IsDoneRole 
};
```
Использование `Qt::UserRole + 1` гарантирует, что наши пользовательские роли не пересекутся со стандартными системными ролями Qt (от 0 до 255).

### 3. Основные методы чтения (Read-Only)
*   `rowCount()`: Возвращает количество задач (`m_items.size()`). Содержит проверку `if (parent.isValid()) return 0;`, которая сообщает фреймворку Qt, что это плоский список, а не древовидная структура.
*   `data()`: Главный метод-провайдер. Получает номер строки (`index`) и нужную роль (`role`), после чего с помощью `switch (role)` отдает либо текст задачи, либо ее статус в виде универсального контейнера `QVariant`.
*   `roleNames()`: Функция-словарь. Связывает числовые C++ константы ролей с текстовыми именами для использования в QML (строка `"description"` соответствует `DescriptionRole`, а `"done"` — `IsDoneRole`).

### 4. Изменение данных (Write)
*   `setData()`: Позволяет QML изменять данные в C++ (например, при клике по чекбоксу). Принимает новое значение, обновляет структуру в `m_items` и обязательно отправляет системный сигнал `emit dataChanged(...)`, чтобы интерфейс перерисовался. Метод `flags()` разрешает редактирование элементов (`Qt::ItemIsEditable`).
*   `addTask()` и `removeItem()`: Методы для добавления и удаления задач. Макрос `Q_INVOKABLE` делает эти методы доступными для прямого вызова из QML-кода. Внутри методов обязательно используются функции-предупреждения `beginInsertRows`/`endInsertRows` и `beginRemoveRows`/`endRemoveRows` для безопасного уведомления графического движка об изменении размеров массива.

## Интеграция C++ и QML (Связующий мост)

Связь между языками устанавливается в главном файле `main.cpp`. Перед загрузкой QML-файла вызывается специальная функция регистрации:
```cpp
qmlRegisterType<ToDoModel>("com.mycompany.todo", 1, 0, "ToDoModel");
```
Это позволяет в `Main.qml` импортировать данный модуль (`import com.mycompany.todo 1.0`) и создать экземпляр модели как обычный QML-компонент:
```qml
ToDoModel {
    id: todoModel
}
```

После этого делегат `TodoDelegate` получает прямой доступ к свойствам через `model.description` и `model.done`, а кнопки интерфейса могут вызывать методы, например, `todoModel.addTask("Текст")` и `todoModel.removeItem(index)`.
