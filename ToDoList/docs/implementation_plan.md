# 📋 Пошаговый план реализации — To-Do List

> Каждый этап — маленький шаг. После каждого этапа у тебя будет **работающий** результат, который можно запустить и увидеть прогресс.

---

## Этап 1: Создание пустого Qt Quick проекта

### Цель
Получить минимальный проект, который **компилируется и запускается** — пустое окно.

### Что делаем
1. Создаём структуру папок проекта
2. Пишем `CMakeLists.txt` — файл сборки
3. Создаём `main.cpp` — точка входа, запускает QML-движок
4. Создаём `Main.qml` — минимальное окно с заголовком

### Файлы которые создадим
```
ToDoList/
├── CMakeLists.txt        ← конфигурация сборки
├── src/
│   └── main.cpp          ← точка входа в приложение
└── qml/
    └── Main.qml          ← главное окно (пока пустое)
```

### Что изучишь
- Как устроен Qt Quick проект
- Что такое `QGuiApplication` и `QQmlApplicationEngine`
- Базовый синтаксис QML (`ApplicationWindow`, свойства `width`, `height`, `title`)

### Результат
🟢 Запускается пустое окно с заголовком "To-Do List"

## Этап 2: Вёрстка интерфейса на чистом QML

### Цель
Сверстать **статичный** (пока без логики) интерфейс списка задач.

### Что делаем
1. Добавляем поле ввода (`TextField`) для новой задачи
2. Добавляем кнопку "Добавить" (`Button`)
3. Создаём `ListView` для отображения списка задач
4. Создаём компонент-делегат (`TodoDelegate.qml`) — как выглядит одна задача:
   - Чекбокс (выполнено / не выполнено)
   - Текст задачи
   - Кнопка удаления

### Файлы которые создадим / изменим
```
qml/
├── Main.qml              ← обновим: добавим layout
└── components/
    └── TodoDelegate.qml  ← [NEW] внешний вид одной задачи
```

### Что изучишь
- QML-компоненты: `ColumnLayout`, `RowLayout`, `TextField`, `Button`
- Создание переиспользуемых компонентов (свой `.qml` файл)
- Свойства `anchors` и `Layout` для позиционирования
- Стилизация элементов (цвета, шрифты, скругления)

### Результат
🟢 Красивый интерфейс с полем ввода, кнопкой и статичным списком задач (данные захардкожены)

## Этап 3: Модель данных на C++ (TodoModel)

### Цель
Создать C++ класс `TodoModel`, который наследуется от `QAbstractListModel` и хранит список задач.

### Что делаем
1. Создаём структуру `TodoItem` (текст + статус выполнения)
2. Создаём класс `TodoModel`:
   - Хранит `QList<TodoItem>` — список задач
   - Переопределяем `rowCount()` — сколько задач в списке
   - Переопределяем `data()` — возвращает данные задачи по индексу
   - Переопределяем `roleNames()` — описывает какие данные доступны в QML

### Файлы которые создадим
```
src/
├── main.cpp              ← обновим: зарегистрируем модель
├── todomodel.h           ← [NEW] заголовочный файл модели
└── todomodel.cpp         ← [NEW] реализация модели
```

### Что изучишь
- Что такое `QAbstractListModel` и зачем он нужен
- Паттерн Model-View — разделение данных и отображения
- Роли модели (`Qt::DisplayRole`, пользовательские роли)
- `Q_INVOKABLE` — чтобы QML мог вызывать C++ методы

### Результат
🟢 Модель создана, но пока с тестовыми данными. ListView в QML показывает их автоматически.

## Этап 4: Связываем C++ модель и QML интерфейс

### Цель
QML использует `TodoModel` из C++ вместо захардкоженных данных. Кнопки в QML вызывают C++ методы.

### Что делаем
1. Регистрируем `TodoModel` в QML через `qmlRegisterType` или контекст
2. В `Main.qml` подключаем модель к `ListView`
3. Реализуем C++ методы:
   - `addTask(QString text)` — добавить задачу
   - `removeTask(int index)` — удалить задачу
   - `toggleTask(int index)` — переключить статус
4. Привязываем кнопки QML к вызовам C++ методов

### Файлы которые изменим
```
src/
├── todomodel.h           ← добавим Q_INVOKABLE методы
├── todomodel.cpp         ← реализуем addTask, removeTask, toggleTask
qml/
├── Main.qml              ← подключим модель
└── components/
    └── TodoDelegate.qml  ← привяжем кнопки к модели
```

### Что изучишь
- Как C++ объекты становятся доступны в QML
- `beginInsertRows()` / `endInsertRows()` — уведомление QML об изменениях
- `beginRemoveRows()` / `endRemoveRows()`
- Сигналы и слоты в контексте Model-View

### Ключевой момент 💡
```cpp
// C++ сторона
void TodoModel::addTask(const QString &text) {
    beginInsertRows(QModelIndex(), rowCount(), rowCount());
    m_tasks.append({text, false});
    endInsertRows();
}
```
```qml
// QML сторона
Button {
    text: "Добавить"
    onClicked: todoModel.addTask(inputField.text)
}
```

### Результат
🟢 Полностью работающий To-Do List: добавление, удаление, отметка выполнения. Но данные **теряются** при закрытии.

## Этап 5: Сохранение данных в JSON

### Цель
Задачи сохраняются в файл `tasks.json` и загружаются при запуске.

### Что делаем
1. Реализуем метод `saveToFile()`:
   - Конвертируем `QList<TodoItem>` → `QJsonArray` → `QJsonDocument`
   - Записываем в файл через `QFile`
2. Реализуем метод `loadFromFile()`:
   - Читаем файл → парсим JSON → заполняем `QList<TodoItem>`
3. Вызываем `loadFromFile()` при запуске (в конструкторе)
4. Вызываем `saveToFile()` после каждого изменения (add/remove/toggle)

### Файлы которые изменим
```
src/
├── todomodel.h           ← добавим методы save/load
└── todomodel.cpp         ← реализуем сериализацию JSON
```

### Формат файла `tasks.json`
```json
[
    {
        "text": "Купить молоко",
        "completed": false
    },
    {
        "text": "Выучить QML",
        "completed": true
    }
]
```

### Что изучишь
- `QJsonDocument`, `QJsonArray`, `QJsonObject` — работа с JSON в Qt
- `QFile` — чтение/запись файлов
- `QStandardPaths` — где хранить данные приложения
- Сериализация/десериализация данных

### Результат
🟢 Задачи **сохраняются** между запусками приложения!
