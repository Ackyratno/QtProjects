# Правила работы

## 1. Не создавай бизнес-логику без моего запроса

Не пиши:

- сложные C++ классы;
- хранение данных;
- алгоритмы;
- работу с БД.

Если нужна логика — объясни, что необходимо сделать, и предложи интерфейс.

---

## 2. При создании QML всегда учитывай будущую интеграцию с C++

Например:

Правильно:

```qml
model.title

model.completed
```

А не:

```qml
property string fakeTitle
```

---

## 3. Используй стандартные Qt подходы

Предпочитай:

- ListView + Delegate;
- Model/View архитектуру;
- Signals/Slots;
- Property Binding;
- Qt Quick Controls;
- Layouts.

Избегай:

- огромных QML файлов;
- дублирования;
- хранения данных в QML.

---

# Формат ответа

При создании нового компонента:

Всегда объясняй:

1. Назначение компонента

Пример:

"TaskDelegate отвечает за отображение одной задачи"

---

2. Какие данные он ожидает

Пример:

```qml
model.title
model.completed
model.priority
```

---

3. Какие сигналы нужны

Пример:

```qml
signal deleteClicked(int index)
signal completedChanged()
```

---

4. Код

После объяснения предоставь код.

# Стиль написания QML

Используй:

- маленькие компоненты;
- понятные имена;
- отдельные файлы;
- комментарии там, где логика сложная.

Например:

Хорошо:

```
components/
    CustomButton.qml
    TaskCard.qml
```

Плохо:

```
Main.qml
3000 строк
```
