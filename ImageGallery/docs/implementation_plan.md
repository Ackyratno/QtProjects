# План реализации: Image Gallery (Mentor Edition - Упрощенный)

Ты абсолютно прав! Для проекта сложности ⭐⭐ многопоточность в C++ — это избыточно (over-engineering). Сканирование путей к файлам через `QDir` работает очень быстро. Главная проблема производительности в галереях — это *отрисовка* и *загрузка самих картинок в память*, а эту проблему мы решим средствами QML (Lazy Loading).

Поэтому мы **убираем** отдельный поток (`ImageScanner`) и максимально упрощаем архитектуру, оставляя только самое важное.

## 1. Архитектура приложения

```text
       UI (QML)
[ GalleryPage.qml ] ---> Отображает сетку (GridView). Сама грузит картинки асинхронно!
          |
          ↓
[ ImageGalleryModel ] -> C++ класс (QAbstractListModel). При создании просто читает 
                         папку через QDir и хранит список путей (QStringList).
```

**Почему так лучше для старта?**
Ты сфокусируешься на главном: как правильно написать `QAbstractListModel` и как связать его с QML. А асинхронность мы переложим на плечи движка QML (свойство `asynchronous: true` у компонента `Image`).

## 4. Этапы разработки (Обновленные)

### Этап 1: Скелет и QAbstractListModel

*   **Моя задача:** Подготовить `Main.qml` и простую версию `GalleryPage.qml`, которая выводит текстовые пути (чтобы проверить, что данные доходят).
*   **Чему учимся:** Базовая реализация `QAbstractListModel` (без потоков) и вывод данных в QML.

### Этап 2: QML GridView и Lazy Loading
*   **Твоя задача:** Модель уже готова. Твоя цель на этом этапе — просто запустить код и убедиться, что всё работает.
