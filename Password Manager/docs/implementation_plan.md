## 1. Архитектурная концепция проекта

Приложение строится по классической многослойной архитектуре с четким разделением ответственности (SoC — Separation of Concerns).

```
+-----------------------------------------------------------------------+
|                            QML Interface                              |
|   (Main.qml, UnlockPage, VaultPage, ItemEditModal, GeneratorModal)    |
+-----------------------------------+-----------------------------------+
                                    |
                       (Q_PROPERTY, Signals, Slots)
                                    v
+-----------------------------------------------------------------------+
|                         C++ Presentation Layer                        |
|   - PasswordModel (QAbstractListModel)                                |
|   - MasterAuthManager (QObject — состояние хранилища: Lock/Unlock)    |
|   - PasswordGenerator (QObject — генератор и расчет энтропии)         |
+-------------------+-----------------------------------+---------------+
                    |                                   |
           (Repository Pattern)                 (Crypto & Security)
                    v                                   v
+-----------------------------------+   +-------------------------------+
|     IPasswordRepository           |   |       CryptoService           |
|  (Интерфейс слоя данных)          |   |  - Генерация ключа (PBKDF2)   |
+-------------------+---------------+   |  - Шифрование (AES-256-CBC)   |
                    |                   |  - Очистка памяти (Zeroize)   |
                    v                   +-------------------------------+
+-----------------------------------+
|     SqlitePasswordRepository      |
|  (QSqlDatabase, QSqlQuery, SQLite)|
+-----------------------------------+
```

### Принципы безопасности (Security First):
1. **Мастер-пароль нигде не сохраняется в открытом виде.** Для проверки используется криптографический хэш с солью (PBKDF2-HMAC-SHA256).
2. **Все данные записей в базе SQLite хранятся в зашифрованном виде (AES-256).**
3. **Ключ шифрования генерируется динамически на основе мастер-пароля** и хранится в оперативной памяти только пока хранилище разблокировано.
4. **Очистка памяти (Memory Zeroing):** буферы с паролями и ключами зануляются (`explicit_bzero` / `std::fill`) сразу после использования.
5. **Безопасность буфера обмена:** скопированный пароль автоматически стирается из буфера через заданное время (например, 30 секунд).

### 🟢 Этап 2: Криптографическое ядро (AES-256, PBKDF2) и безопасность памяти

#### 🎯 Цель этапа
Разработать надежный C++ модуль для шифрования и дешифрования данных с использованием промышленного алгоритма **AES-256-CBC** и функции деривации ключа из пароля **PBKDF2-HMAC-SHA256**.

#### 📚 Что вам нужно изучить:
1. **Криптографические основы:**
   - Разница между симметричным шифрованием (AES) и хэшированием (SHA-256 / PBKDF2).
   - Зачем нужна «соль» (Salt) и вектор инициализации (IV — Initialization Vector).
   - Почему нельзя использовать чистый AES в режиме ECB, а нужно использовать CBC или GCM.
   - Деривация ключа: почему нельзя шифровать напрямую паролем пользователя, а нужно прогонять через PBKDF2 (100 000+ итераций).
2. **Работа с OpenSSL EVP API / Qt Crypto:**
   - Использование `EVP_CIPHER_CTX_new`, `EVP_EncryptInit_ex`, `EVP_EncryptUpdate`, `EVP_EncryptFinal_ex`.
   - `QPasswordDigestor::deriveKeyPbkdf2` из состава Qt Core (или OpenSSL `PKCS5_PBKDF2_HMAC`).
3. **Безопасность памяти (Secure Zeroing):**
   - Почему оптимизатор компилятора может «вырезать» обычный `memset(ptr, 0, size)` (Dead Store Elimination).
   - Использование `OPENSSL_cleanse` или безопасного зануления памяти.

#### 🔨 Зона ответственности:
- **Вы (C++):**
  - Реализовать класс `CryptoService` (`cpp/security/CryptoService.h`, `.cpp`):
    - `QByteArray deriveKey(const QString& masterPassword, const QByteArray& salt, int iterations = 100000);`
    - `QByteArray encrypt(const QByteArray& plainData, const QByteArray& key, const QByteArray& iv);`
    - `QByteArray decrypt(const QByteArray& cipherData, const QByteArray& key, const QByteArray& iv);`
    - `QByteArray generateRandomBytes(int length);`
  - Написать юнит-проверку (в `main.cpp` или отдельным тестом): убедиться, что `decrypt(encrypt("secret")) == "secret"`.
- **Я (AI):**
  - Подготовить архитектурную схему процесса шифрования/дешифрования.
  - Помочь с разбором ошибок работы с сырыми буферами (`QByteArray`, `unsigned char*`).

#### ✅ Результат этапа:
Класс `CryptoService` корректно шифрует строку в бинарные данные / Base64 и без потерь восстанавливает исходный текст.

## 5. Альтернативные технические решения (Trade-offs)

При разработке перед нами встанут несколько архитектурных развилок:

### 1. Библиотека криптографии: OpenSSL vs Qt Crypto (QPasswordDigestor)
* **Вариант А (OpenSSL EVP API):**
  * *Плюсы:* Общепринятый мировой стандарт, поддержка аппаратного ускорения AES-NI, максимальный контроль над памятью (`OPENSSL_cleanse`).
  * *Минусы:* Требует отдельной линковки OpenSSL в CMake.
* **Вариант B (Только встроенный Qt 6 QPasswordDigestor + QCryptographicHash):**
  * *Плюсы:* Не требует внешних зависимостей для хэширования.
  * *Минусы:* В стандартном Qt нет встроенного симметричного шифратора AES (пришлось бы писать реализацию AES вручную или использовать сторонний легковесный заголовочный файл).
* **Рекомендация:** Использовать **OpenSSL** для AES-256 и деривации ключей. Это даст реальный опыт работы с промышленными криптобиблиотеками.

---

### 2. Стратегия расшифровки данных в модели:
* **Вариант А (On-demand Decryption — расшифровка по требованию):**
  * В `PasswordModel` хранятся только зашифрованные байты. Расшифровка конкретного пароля происходит только в момент, когда пользователь нажимает кнопку "Показать" или "Скопировать".
  * *Плюсы:* Максимальная безопасность RAM — даже при дампе памяти открытых паролей там нет.
  * *Минусы:* Чуть больше кода в C++ модели.
* **Вариант B (In-memory Decrypted Cache — расшифровка всего при разблокировке):**
  * Все пароли расшифровываются один раз при вводе мастер-пароля и хранятся в векторе `std::vector<PasswordItem>`.
  * *Плюсы:* Простая реализация `QAbstractListModel::data()`.
  * *Минусы:* Все пароли лежат в оперативной памяти в открытом виде.
* **Рекомендация:** Реализовать **Вариант А (On-demand)** как наилучшую практику информационной безопасности.
